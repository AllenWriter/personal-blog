## [unplugin-auto-import](https://github.com/antfu/unplugin-auto-import)

**Automatically imports Vue 3 APIs. Supports auto-importing from `vue`, `vue-router`, `vue-i18n`, `@vueuse/head`, `@vueuse/core` and more.**

What it looks like

```javascript
// Before
import { ref, computed } from 'vue'
const count = ref(0)
const doubled = computed(() => count.value * 2)

// After
const count = ref(0)
const doubled = computed(() => count.value * 2)

// Before
import { useState } from 'react'
export function Counter() {
  const [count, setCount] = useState(0)
  return <div>{count}</div>
}

// After
export function Counter() {
  const [count, setCount] = useState(0)
  return <div>{count}</div>
}
```

Install

```sh
npm i -D unplugin-auto-import
```

[Full configuration](https://github.com/antfu/unplugin-auto-import#configuration)

```javascript
import { defineConfig } from 'vite'
import AutoImport from 'unplugin-auto-import/vite'

export default defineConfig({
  plugins: [
    AutoImport({
      imports: ['vue', 'vue-router', 'vue-i18n', '@vueuse/head', '@vueuse/core'],
      dts: 'src/auto-import.d.ts',
      // You can choose where auto-import.d.ts is generated (the root directory by default). I recommend setting it to 'src/auto-import.d.ts'
    }),
  ],
})
```

How it works: it automatically generates an auto-imports.d.ts file for code hints, like this

```typescript
// Generated by 'unplugin-auto-import'
// We suggest you to commit this file into source control
declare global {
  const ref: typeof import('vue')['ref']
  const reactive: typeof import('vue')['reactive']
  const computed: typeof import('vue')['computed']
  const createApp: typeof import('vue')['createApp']
  const watch: typeof import('vue')['watch']
  const customRef: typeof import('vue')['customRef']
  const defineAsyncComponent: typeof import('vue')['defineAsyncComponent']
}
export {}
```

> **caution**
> Note that since there are no local imports, "go to definition" jumps to auto-imports.d.ts first, and then to the original definition.

### Reactivity syntax sugar

[Reactivity Transform | Vue.js (vuejs.org)](https://vuejs.org/guide/extras/reactivity-transform.html)

With `$ref`, you don't need `.value` when you use it. Here's a demo

```javascript
import { $ref, $$ } from 'vue/macros' // $ref comes from the vue/macros package

// bind ref as a variable
let count = $ref(0)

// assignments are reactive
count++

// get the actual ref
console.log($$(count)) // { value: 1 }
```

- You can use `$()` to destructure a reactive object, so you don't have to write `.value`
- You can use `$$()` to get the original ref object

Add `reactivityTransform: true` in the vite.config.ts file

```javascript
plugins: [
  vue({
    reactivityTransform: true,
  }),
]
```

You can use `vue/macros` from unplugin-auto-import, so there's no need to import it manually.

```javascript
AutoImport({
  imports: ['vue/macros'],
  dts: true,
})
```

## [unplugin-vue-components](https://github.com/antfu/unplugin-vue-components)

**Automatically imports UI libraries on demand. Many component libraries recommend this way of importing, such as Element Plus and Ant Design Vue.**

Install

```sh
npm install unplugin-vue-components -D
```

```javascript
import { defineConfig } from 'vite'
import Components from 'unplugin-vue-components/vite'
import {
  ElementPlusResolver,
  AntDesignVueResolver,
  VantResolver,
  HeadlessUiResolver,
  ElementUiResolver
} from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    Components({
      // UI library resolvers; you can also write your own
      resolvers: [
        ElementPlusResolver(),
        AntDesignVueResolver(),
        VantResolver(),
        HeadlessUiResolver(),
        ElementUiResolver()
      ]
    })
  ]
```

The plugin generates a components.d.ts file for UI library components and their paths, like this

```typescript
// generated by unplugin-vue-components
// We suggest you to commit this file into source control
// Read more: https://github.com/vuejs/vue-next/pull/3399

declare module 'vue' {
  export interface GlobalComponents {
    ElAside: typeof import('element-plus/es')['ElAside']
    ElButton: typeof import('element-plus/es')['ElButton']
    ElContainer: typeof import('element-plus/es')['ElContainer']
    ElHeader: typeof import('element-plus/es')['ElHeader']
    ElIcon: typeof import('element-plus/es')['ElIcon']
    ElMain: typeof import('element-plus/es')['ElMain']
  }
}

export {}
```

Any component you use gets imported automatically, and you can also import your own components.

```javascript
import { defineConfig } from 'vite'
import Components from 'unplugin-vue-components/vite'

export default defineConfig({
  plugins: [
    Components({
      // Where to look for components; defaults to src/components
      dirs: ['src/components'],
      extensions: ['vue'],
      // Where to generate the config file
      dts: 'src/components.d.ts',
    }),
  ],
})
```

## [unplugin-vue-define-options/vite](https://github.com/sxzz/unplugin-vue-define-options)

**Lets you define component name, inheritAttrs, props and emits with defineOptions in the script setup syntax sugar.**

Install

```sh
npm i unplugin-vue-define-options
```

```javascript
import { defineConfig } from 'vite'
import DefineOptions from 'unplugin-vue-define-options/vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue(), DefineOptions()],
})
```

Set types in `tsconfig.json` as shown below:

```json
{
  "compilerOptions": {
    "types": ["unplugin-vue-define-options"]
  }
}
```

Otherwise, in a TS project you'll get the error **Cannot find name 'defineOptions'**. Usage looks like this

```vue
<script setup lang="ts">
import { useSlots } from 'vue'
defineOptions({
  name: 'Foo',
  inheritAttrs: false,
  props: {
    msg: { type: String, default: 'bar' },
  },
  emits: ['change', 'update'],
})
const slots = useSlots()
</script>
```

Output

```vue
<script lang="ts">
export default {
  name: 'Foo',
  inheritAttrs: false,
  props: {
    msg: { type: String, default: 'bar' },
  },
  emits: ['change', 'update'],
}
</script>

<script setup>
const slots = useSlots()
</script>
```

If all you want is to **set the component name**, the plugin [vite-plugin-vue-setup-extend](https://github.com/vbenjs/vite-plugin-vue-setup-extend) may be a better fit. You just add a name attribute to the script tag.

```vue
<template>
  <div>hello world {{ a }}</div>
</template>

<script lang="ts" setup name="App">
const a = 1
</script>
```

## [vite-plugin-mock](https://github.com/vbenjs/vite-plugin-mock)

**Provides mock services for local development and production.**

Install

```sh
npm i mockjs vite-plugin-mock
```

```javascript
import { UserConfigExport, ConfigEnv } from 'vite'

import { viteMockServe } from 'vite-plugin-mock'
import vue from '@vitejs/plugin-vue'

export default ({ command }: ConfigEnv): UserConfigExport => {
  return {
    plugins: [
      vue(),
      viteMockServe({
        // default
        mockPath: 'mock',
        localEnabled: command === 'serve',
      }),
    ],
  }
}
```

## [vite-plugin-pages](https://github.com/hannoeru/vite-plugin-pages)

**File-system-based dynamic routing.**

Install

```sh
npm install -D vite-plugin-pages
npm install vue-router
```

```javascript
import Pages from 'vite-plugin-pages'

export default {
  plugins: [
    Pages({
      dirs: 'src/views',
    }),
  ],
}
```

The traditional way to write routes

```javascript
// 1. Define route components.
const Home = { template: '<div>Home</div>' }
const About = { template: '<div>About</div>' }

// 2. Define some routes
const routes = [
  { path: '/', component: Home },
  { path: '/about', component: About },
]

// 3. Create the router instance and pass the `routes` option
const router = VueRouter.createRouter({
  routes,
})
```

This plugin instead imports all the vue files under pages (views) as routes, with its own routing rules, similar to nuxt.js

```main.js
import { createRouter } from 'vue-router'
import routes from '~pages'

const router = createRouter({
  // ...
  routes,
})
```

## [vite-plugin-vue-layouts](https://github.com/JohnCampionJr/vite-plugin-vue-layouts)

Used together with `vite-plugin-pages`, it adds dynamic layouts on top of the generated page routes.

Install

```sh
npm install -D vite-plugin-vue-layouts
```

```typescript
import Vue from '@vitejs/plugin-vue'
import Pages from 'vite-plugin-pages'
import Layouts from 'vite-plugin-vue-layouts'

export default {
  plugins: [Vue(), Pages(), Layouts()],
}
```

Add a layout setting in the corresponding single-file page component, and the route will switch to that layout, embedding the page inside it.

```vue
<route lang="yaml">
meta:
  layout: users
</route>
```

## [vite-plugin-purge-icons](https://www.npmjs.com/package/vite-plugin-purge-icons)

**An easy way to use [Iconify](https://icon-sets.iconify.design/) icons.**

Install

```sh
 pnpm add @iconify/iconify
 pnpm add vite-plugin-purge-icons @iconify/json -D
```

```javascript
import PurgeIcons from 'vite-plugin-purge-icons'

export default {
  plugins: [
    PurgeIcons({
      /* PurgeIcons Options */
    }),
  ],
}
```

Import `@purge-icons/generated` in main.js

```javascript
import { createApp } from 'vue'
import App from './App.vue'

import '@iconify/iconify'
import '@purge-icons/generated'

createApp(App).mount('#app')
```

Usage

In an HTML file, set the class to iconify and data-icon to the icon you want from Iconify (just copy it from the official site)

```html
<span class="iconify" data-icon="system-uicons:browser-alt" data-inline="false" />
```

Of course, you can also wrap it in your own Icon component, like this.

```html
<Icon icon="ion:settings-outline" :size="30" />
```

Or use [Iconify for Vue](https://docs.iconify.design/icon-components/vue/index.html), the Vue 3 version.

## [vite-plugin-windicss](https://github.com/windicss/vite-plugin-windicss)

Install

```sh
npm i -D vite-plugin-windicss windicss
```

```javascript
import WindiCSS from 'vite-plugin-windicss'

export default {
  plugins: [WindiCSS()],
}
```

The main reason I use Windi CSS is that [attributify mode](https://cn.windicss.org/features/attributify.html) is just too good (I expect it to become a trend). Attributify is optional by default, and you can enable it in your windi config.

```typescript
import { defineConfig } from 'windicss/helpers'

export default defineConfig({
  attributify: true,
})
```

Then use them as needed:

```html
<button bg="blue-400 hover:blue-500 dark:blue-500 dark:hover:blue-600" text="sm white" font="mono light" p="y-2 x-4" border="2 rounded blue-200">Button</button>
```

Syntax

```
(variant[:-]{1})*key? = "((variant:)*value)*"
```
