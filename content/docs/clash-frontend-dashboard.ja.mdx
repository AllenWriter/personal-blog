> **tip**
> Clashの変換プラットフォームをただ使いたいだけで、仕組みには興味がないなら、以下の手順に沿って変換フロントエンドを自分でデプロイできます。

## [はじめに](#preface)

ネット上には、複雑な宝塔（BaoTa）パネルを使ってClashのフロントエンドを構築するチュートリアルがたくさんあります。しかし、ほぼすべてが宝塔パネルを通すことを前提にしています。初心者はそれに従うこともできますが、それでもまだ「速く」はありません。もしClashが何か分からないなら、まずは[《Clashとは？》](/docs/what-is-clash)をお読みください。

> **caution**
> 中国版の宝塔パネルでは、携帯電話番号の入力も求められます。

そもそも、これは第一原理に反しています。私の目的ははっきりしています。必要ないサービスを、わざわざ余分にインストールする理由がどこにあるのでしょうか。

今では強力な[Vercelプラットフォーム](https://vercel.com/dashboard)があり、シンプルなWebアプリケーションなら十分すぎるほど対応できます。GitHubリポジトリから直接ワンクリックでデプロイでき、必要なのはフロントエンド用のドメインを設定することと、バックエンド用のコンテナを一つ引っ張ってくることだけです。何より、これは永続的に無料で使えます。

## 前提条件

- GitHubアカウント
- VPS
- VPS上にデプロイされた[Nginx Proxy Manager](https://nginxproxymanager.com/)
- フロントエンド用のドメイン
- バックエンド用のドメイン

## はじめる

では、変換プラットフォームを構築するには何ステップ必要でしょうか。

1. フロントエンドページを構築する
2. バックエンドサービスをデプロイする
3. ドメインを設定する

Clash変換プラットフォームは、主にフロントエンドページとバックエンドサービスで構成されます。フロントエンドページは主に[sub-web](https://github.com/CareyWang/sub-web)が提供し、バックエンドサービスはDockerの形で直接動かせるので、より手軽です。

## 1. フロントエンドページを構築する

では、あらゆる変換プラットフォームの元になっているプロジェクト、有名な[CareyWang/sub-web](https://github.com/CareyWang/sub-web)を探してください。そして右上のForkボタンを軽くクリックします。Forkとは「フォーク（フォークで刺す）」の意味で、自分のお皿に「刺して」持ってくるイメージです。（ちなみにここでのForkは動詞で、専門的には「分岐」、つまり自分のリポジトリに複製することを指します。）

### コードをコミットする

修正が終わったら、GitHubでコミットするのを忘れないでください。

## 2. Vercelに公開する

この手順はとても簡単です。[Vercelプラットフォーム](https://vercel.com/new)にアクセスし、先ほど修正したClashリポジトリをImportします。

それからDeployをクリックします。しばらく待つと、何もなければエラーが出ます。

これはVercelのデフォルトのNodeバージョンが20以上になっているためで、このプロジェクトはそこまで高いNodeバージョンを必要としません。そのため、プロジェクトの設定に入って変更する必要があります。Setting → Generalに進み、Node.js Versionを切り替えてください。

デプロイが完了すると、Vercelは無料のドメインを自動で割り当てます。それでも、Domainsで自分のフロントエンドドメインをバインドすることをお勧めします。この手順はドメイン管理画面で行い、ドメインをVercelから割り当てられたアドレスに向けるだけです。

## 3. バックエンドアプリケーションをデプロイする

VPSで以下のDockerイメージを取得します。

```bash
docker run -d --restart=always -p 25500:25500 tindy2013/subconverter:latest
```

イメージのインストールが終わったら、以下のコマンドでサービスが正しく動いているか確認します。

```bash
curl http://localhost:25500/version
```

`subconverter vx.x.x backend`が返ってくれば、サービスは起動しています。

## 4. バックエンドのドメインをサービスのポートに向ける

Nginx Proxy Manager（NPM）の管理画面にログインし、`Proxy`を追加して、バックエンドのドメインを入力します。IPの欄には`127.0.0.1`を入れないでください。代わりにVPSのパブリックIPとポート番号を入力します。例えば`214.124.214.25`のように、Forward Portには25500を入力します。

あわせてSSL証明書も有効にします。

バインドが完了したら、バックエンドのドメインにアクセスしてください。Nginxのエラー画面ではないページが表示されれば、バックエンドの構築は成功です。

ここまでできれば、あなた自身のClash購読変換プラットフォームを存分に使えます。
